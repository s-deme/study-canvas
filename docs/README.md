## 正本と数え方

- 登録先：`web/exams.mjs` と既存・追加教材の試験定義。試験IDでまとめ、年度・科目は問題側で管理します。
- 現在の登録問題数：`build/private/web/material/` の実際の問題ファイル。`catalog.mjs` と `manifest.json` の件数・パック情報・SHA-256を照合して集計します。同じ `examId::id` は二重計上せず、重複時は停止します。
- GitHub候補の変換・非収録理由：`private-data/github-candidates/prepared/report.json`。登録数はビルド後の値を使います。取得済み・変換済み・収録済み・内容検証済み・配備済みはそれぞれ別の状態です。
- 取得記録：公式原本経由は `private-data/github-material/` の取得記録と `github-sources.json`、候補経由は `private-data/github-candidates/acquisition.json`。両方に現れるリポジトリ数やファイル数を単純加算しません。再取得判定は既存の各取得処理へ任せます。
- 件数は「その試験で演習できる出題数」です。年度違いの再出題や試験別の共通午前Ⅰは別出題です。意味が同じ問題の全体件数ではありません。GitHub候補の本文等の一致判定と公式PDF・問題番号による判定は、既存のビルド処理で行います。

教材本文・原本・画像・学習記録をdocsへ複製しません。公開版、本人用ローカル版、クラウド版、ブラウザ持込の件数は混ぜません。合成テストデータ・未収録候補・取得しただけの冊子も登録問題数へ含めません。

環境・自然科学の公式過去問と収録保留候補は [環境・自然科学の取り込み記録](environment-import.md)、公務員試験は [公務員試験の取り込み記録](civil-import.md) を参照してください。

1. 対象教材の取得・変換・検証を行います。個別コマンドは上記の取り込み文書を参照します。
2. `npm run build:private` で重複除外後の教材を生成します。
3. `npm run inventory:exams` で試験管理表・取り込み状況・GitHub調査台帳を同時に更新します。SHA-256・件数・問題IDの重複などの不整合があれば停止します。
4. 詳細文書にはその作業の検証範囲・未検証事項・非収録理由を記録します。現在の合計は生成文書へのリンクで案内します。

生成文書は最後に成功したビルドのスナップショットです。原本取得や変換だけでは更新されません。本人用ビルドがない環境では登録数0・取り込み状況未確認になります。クラウドの配備状況は実際の配備記録を確認し、ローカルへの追加だけで配備済みとしません。
