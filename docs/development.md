# 開発と公開対象

ローカル開発、自動チェック、公開ファイルと非公開データの扱いをまとめています。クラウドへの配置は [クラウド設定](cloud.md)、既存の検証記録は [検証結果](verification-web.md) を参照してください。以下のコマンドとファイルパスはプロジェクトルートを基準にしています。

## プロジェクト構成

- `web/`：ブラウザー画面、学習処理、問題登録と学習処理・形式確認用サンプル。
- `functions/` と `schema.sql`：本人限定ログインとCloudflare D1への同期。
- `checks/`：Web・同期・クラウド設定・ローカルランタイムの検証。
- `scripts/`：ローカルクラウド設定の準備。
- `docs/`：利用・問題形式・クラウド設定・開発のガイドと検証記録。
- `.github/workflows/ci.yml`：`main`へのpush・プルリクエスト時のテスト・Workerビルド・ローカルランタイム検証。

全体の自動チェックとクラウドのローカル検証にはNode.js 24以上を使います。

```powershell
npm ci
npm run check
npm run build:cloud
npm run check:runtime
```

GitHub Actionsには本番配備の認証情報を登録しません。本番更新は、[手動配備の手順](cloud.md#githubでのチェックと手動配備)に従って手元から実行します。

## ローカル版と学習処理のチェック

`web/` がローカルで配信するファイル一式です。ローカル版はパッケージのインストールやビルドは不要です。クラウド版には `functions/` とD1が必要です。問題はファイル選択から取り込み、ブラウザまたは本人専用のクラウドに保存します。`web/` の問題データは形式確認用の自作サンプルだけです。公式問題・図表・問題集は置きません。すべての試験を問題未登録の状態から使います。

Node.js 18以上で処理のチェックを実行できます。

```powershell
node checks/web-check.mjs
```

教材を含まない240件のダミーデータで、100通りの模試抽出、選択肢の復元、採点、スキップ、通常演習と模試の記録タイミング、時間切れ、バックアップ検証、保存失敗と別タブの競合を確認します。

検証済み・未検証の範囲は [Web版の検証結果](verification-web.md) を参照してください。

## 非公開教材と以前の記録

この作業環境にあった240問は `private-data/questions.json` へ移動して保管しています。Git管理・静的配信・Workerへの組み込みから除外し、GitHubや配布ZIPには含めません。以前のスクリーンショットとコンパイル済みWorkerも `private-data/` に退避しています。このフォルダは公開リポジトリには存在しません。

手元で使う場合は、画面の「問題を取り込む（JSON）」で非公開ファイルを選択します。問題ファイルを `web/` にコピーしたり、プロジェクト全体をHTTP配信したりしないでください。ローカルでは `--directory web` を指定します。

旧教材の回答記録・ブックマーク・途中の演習は問題文なしで保持します。同じ `original:` IDの教材を取り込むと再び集計・復習・再開できます。教材が未登録の間は該当問題を集計に含めず、途中の演習を自動採点しません。模試の元の締切は保持し、教材を再登録した後で時間切れを判定します。取り込んだ問題も合計2000問までです。

ローカルの変更は既存のクラウド配信へ自動反映されません。更新後の構成のビルド・再配備と、以前の配備・プレビューURLや配布物の確認は別途必要です。

`npm run check` とクラウド開発・ビルド・配備の前処理で、`web/` の配信ファイルを許可リストで検査します。問題ファイルや未承認の追加ファイルがある場合は停止します。形式確認用見本と、手元に非公開教材がある場合は静的ファイル・Workerへの問題文の混入も確認します。配布する場合は公開対象ファイルのみを使用してください。

## 複数試験と公開サンプルのチェック

`npm run check` は旧機能に加え、試験間の記録分離、4種類の解答形式、旧保存データの移行、JSON・CSV、問題未登録の初期状態、以前の同梱問題の記録保持、複数試験の同期を検証します。

実ブラウザの検証は隔離したヘッドレスChromeをポート9238で起動してから `npm run check:browser` を実行します。使い捨ての認証付きローカルサーバーとSQLite DBを8769で起動し、利用者の実クラウドには接続しません。検証画像は `dist/screenshots/` に保存します。別ポートの隔離Chromeを使う場合は、環境変数 `STUDY_CANVAS_BROWSER_URL` に `http://127.0.0.1:ポート` を指定できます。

公開するサンプルは `web/sample-questions.json`、`web/sample-questions-v2.json`、`web/sample-questions.csv` のみです。`web/catalog.mjs` の初期問題一覧は空で、登録した問題は `state.custom` に保存します。公開チェックは静的ファイルの許可リスト、サンプルの件数・出典、空の初期問題一覧、Git公開候補を検査します。

以前のSG・FE・簿記の61問と図表、生成スクリプトは手元の `private-data/retired-material/` に保管し、Git・静的配信・Workerの対象から外しています。保存データの互換性のため問題IDの識別だけを維持し、問題本文は同梱しません。手元に非公開教材がある場合は公開ファイルとWorkerにその本文・解説が混入していないことも検査します。

Git管理されたプロジェクトでは、公開候補の取得に失敗した場合もチェックを停止します。非公開教材、`wrangler.local.jsonc`、`.dev.vars`、`.env`、生成物を強制的にGitへ追加しても公開チェックで拒否します。`checks/publication-guard-check.mjs` は使い捨てリポジトリとダミーファイルで、この拒否と安全な設定例の許可を検証します。
