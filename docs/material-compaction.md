# 教材の文字化と配信容量削減

原本PDF、既存の取り込み結果、最後に成功した `build/private/` を保持したまま、配信用の派生ビルドを作る。問題ID・年度・出典・順序・正解の選択肢インデックス・学習記録用索引は維持する。今回の作業でコミット・push・配備は行わない。

## 最初の軽量化の実測結果（2026-10-09・ローカル検証済み）

GBは10億バイト。転送は実施せず、公開対象の実ファイルを集計した。

| 対象 | 変更前 | 変更後 | 削減率 |
| --- | ---: | ---: | ---: |
| 教材の配信元 `web/` | 7,154,810,653 bytes | 3,555,400,541 bytes | 50.31% |
| 静的配信ファイル（画像バンドル・旧URL互換を含む） | 7,129,965,179 bytes | 3,538,648,470 bytes | 50.37% |
| 静的配信ファイル＋コンパイル済みWorker | 7,141,086,959 bytes | 3,549,770,251 bytes | 50.29% |
| 静的配信ファイル数 | 4,519 | 3,630 | — |

198,268問・2,572パックを維持。既存の画像なし114,210問に、原本PDFから直接文字化した28問を加え、画像なしは114,238問。残り84,030問は画像を保持し、文字だけでの再現を今回保証しない理由を記録した。既に本文が文字になっている画像併用問題もこの件数に含む。

55,315画像参照で可逆WebPを採用。元画像・音声ファイルの完全一致重複は3,485件。最終配信用の物理画像・音声は52,304ファイルで、新旧107,619 URLを提供する。旧PNG URLの互換対応は55,315件。音声はバイト列を維持している。

原本・中間生成物・旧資料の `private-data/` は約20.445GBあり、そのうちPDFは約9.890GB。教材配信元の画像・音声は変更前約6.752GB（PNG約6.378GB、音声約0.374GB）。旧配信候補・配備中間物を含む `build/private-cloud/` 全体の約14.284GBと、実際の配信対象約7.130GBを区別した。原本・旧生成物を削除していないため、ローカルディスク容量の削減は目的としていない。

検証結果:

- 全198,268問のID・順序・出典・年度・解答形式・正解対応・維持すべき本文を比較し、全画像参照とハッシュを確認した。
- 全画像の変換時に復元画素を比較し、透過画像と破損キャッシュの再生成もテストした。
- 全体再実行で、問題パック・画像マッピング・ハッシュ・生成容量が同じになった。
- 隔離Chromeで文字、Markdown表、画像の表、数式、図・凡例、スキャンの6画面を確認。320/390/1100px幅のはみ出し、採点、途中再開、旧PNG URLの読み込みを検査し、保存画面を目視した。
- 最終パッケージで段階取得・検索・一覧・模試・画像拡大・端末間同期を検査。コンパイル済みWorkerで本人認証・全新旧URL・258試験の同期・競合・Range/音声・不正ID・CSRFの検査が合格した。
- 既存 `npm run check` と新しいPython安全条件検査が合格した。

詳細は公開対象外の `build/material-compaction-summary.json`、完成派生ビルドの証跡、および完成パッケージの `capacity-report.json`・`verification.json` に保存。現在の完成候補は `build/private-cloud/current.json` から参照する。

全問題の目視照合、全スキャンの新規OCRと手動校正、本番配備後の本人操作、実スマートフォンでの確認は未実施。新しい表・数式の自動文字化は行わず、不確かなものは画像のまま保持する。

## 生成と検証

```powershell
npm run build:private-compact
node scripts/package-private-cloud.mjs --compact
node scripts/run-private-cloud.mjs build
npm run check:private-cloud
```

ここまでのコマンドはローカル生成と検査のみ。`build:private-cloud` は文字化・可逆圧縮を経由する。`deploy:private` は既存の配備コマンドなので、生成だけを行うときには実行しない。

`build/private-compact/current.json` は完成した派生ビルドを指す。失敗した処理はこのポインターを更新しない。原本の取り込み処理を再実行しても、軽量化はその成功ビルドから適用するため、増分追加を失わない。原本ビルドが更新された場合、古い派生ビルドのパッケージ化を拒否する。

## 文字化の判定

既存IPA取り込みの原本URL・SHA-256・問題区切り・画像領域を再利用する。直接抽出したPDF本文と登録済み補助本文が一致し、問題文とア〜エの選択肢を一意に分割できる単純な文章を文字化する。原本の文字を使用し、数字・符号・単位・否定表現を推測で修正しない。選択肢の改行を表示し、選択肢本文も検索対象に含める。

回転、注釈、図形、表罫線、写真、文字欠損、強調、上下付き文字、複数列、数式・コード、照合不一致は画像を保持する。結合セルのある表や数式を不確かな文字列に置換しない。既存Markdown表・既存文字式の表示は継続する。スキャンの既存OCRは補助本文として保持し、今回、自動OCRだけで原本画像を外すことはしない。

画像は寸法・RGB/RGBA画素・透明度を維持する可逆WebPへ変換し、デコード後の全画素を比較する。元より小さくなる画像だけ採用する。音声と対象外の画像形式はバイト列を維持する。同一ファイルのSHA-256をキャッシュ名とするため、重複した原本画像は同じ派生画像を参照する。中断後は検証済みキャッシュを再利用し、壊れたキャッシュを再生成する。

## 証跡と公開対象

完成ビルドの `compaction-report.json` に前後の実測容量・件数・検査結果、`text-evidence.json` に文字化した問題と原本領域、`asset-evidence.json` に原画像・派生画像・復元画素のハッシュ、`review.json` に画像を保持した問題と理由を保存する。これらは `web/` の外に置き、配信しない。

配信対象はアプリ、本文パック、必要な試験別索引、参照される画像・音声のみ。原本PDF、OCRキャッシュ、画像の座標ファイル、旧ビルド、未参照の画像、取り込み監査の中間JSONは含めない。パッケージ処理は従来の画像バンドル・本人認証・同期検証を再利用する。D1/R2への新規移行、依存関係の追加、原本の削除は行わない。

既存の編集済み問題・バックアップに保存されたPNG URLは、配信時に同じ画素のWebPへ解決する。画像バイト列を二重に配信せず、バンドル索引に旧URLを追加する。文字化した28問の元画像も既存の編集済み問題用に約1.2MB保持する。軽量化ステージの直接プレビューと異なり、旧URLの互換性はパッケージ化した配信候補で検査する。

全問題の目視照合は、自動検査・代表画面の検査と区別する。画像保持件数は誤りの件数ではなく、文字による完全再現を今回保証しない件数である。

スキャン代表例（2009年度秋期NW午前Ⅱ・問1）は日本語・英語OCRを実行して原本と照合した。選択肢 `0.02` が `002`、`1.6` が `16` になったため、OCR本文への置換を採用しなかった。結果は `ocr-representative.json` に要確認として保存する。全スキャンの新規OCRや全問題の手動校正は実施していない。

## 追加の軽量化（2026-10-09）

以下は追加処理後の完成配信候補の実測値。前回と同じく、GBは10億バイトで、静的ファイルとコンパイル済みWorkerを数えた。

| 対象 | 前回 | 今回 | 追加削減 |
| --- | ---: | ---: | ---: |
| 配信対象の総容量 | 3,549,770,251 bytes | 3,404,090,277 bytes | 145,679,974 bytes（4.10%） |
| 配信対象のJSON | 378,715,058 bytes | 255,054,195 bytes | 123,660,863 bytes（32.65%） |
| 原本PDFから画像を外して文字化した問題 | 28問 | 519問 | 491問追加 |
| 画像なしの問題 | 114,238問 | 114,729問 | 491問追加 |

最初の7,141,086,959 bytesからは52.33%削減。全198,268問・2,572パックを維持し、83,539問は画像を保持した。配信対象は3,625ファイル、物理画像・音声52,304件、新旧互換URL107,648件。演習では新たに文字化した問題の画像を取得しないが、保存済み編集用の互換画像は残している。

今回の完成候補で、全198,268問のID・順序・本文・正解・索引、参照される51,906個の画像・音声ハッシュを再比較し、519問すべてを原本PDF・切り出し画素・最新の文字化条件と再照合した。変換時は互換画像を含む全画像の復元画素も検査した。コンパイル済みWorkerで全107,648 URLの画像・音声ハッシュ、本人認証、Range/音声、258試験の同期・途中再開・競合・不正ID・CSRFが合格した。

隔離Chromeで従来の6種類にFP・食品衛生・電気分野の文字化例を加えた9種類を320/390/1100px幅で検査し、追加3画面の保存画像も目視した。旧PNG URL、採点、途中再開、段階取得、検索、一覧、模試、画像拡大、端末間同期も完成パッケージで合格した。既存の `npm run check`、Python安全条件検査、増分取り込みの回帰検査も合格。全問題の目視、実スマートフォンの操作、本番配備は未実施で、原本と旧ビルドは保持している。

実測値と完成候補への参照は `build/material-compaction-additional-summary.json`、完成パッケージの `capacity-report.json`・`verification.json`・`browser-verification.json` に保存した。前回の集計は比較用に保持している。

可逆WebPを `method=6` で再評価する。以前の可逆WebP・新しい可逆WebP・原PNGを比較し、小さい結果を保持する。寸法・RGB/RGBA画素・透過は変更せず、再圧縮と以前の結果を採用する場合の両方で復元画素を比較する。圧縮設定をキャッシュに記録し、更新後は検証済みの結果を再利用する。16画像の比較では `method=1` の2,414,280 bytesに対し `method=6` は2,364,944 bytesだった。このサンプルの削減率を全体の実測値として扱わない。

同一SHA-256のPNGは一つの圧縮ジョブにまとめ、すべての参照先に結果を戻す。Windowsで複数プロセスが同じキャッシュを同時に更新する競合を防ぐ。元PNGを採用する場合のURLと、音声のURL・バイト列は維持する。この動作は同一画像の重複ジョブ数と音声のバイト列を検査する回帰チェックに含める。

文字化の照合対象を、保存済みの全分野のPDF領域記録とFPの設問領域へ広げる。PDFのSHA-256、登録画像との対応、切り出した画素を確認し、既存の本文があれば文字も照合する。単純なア〜エの選択式は選択肢を分離し、それ以外は原本の全文を共通本文に保持する。後者では問題番号、共通資料、選択肢の順序、正解、既存の法令基準日などの指示を維持する。装飾・図表・数式・スキャン・曖昧な列・解答画像を含むものは画像を保持する。同じ原本領域の照合結果は処理中に再利用するが、原画像のハッシュは毎回確認する。

本文パックと試験別索引の全行で同じ値を `defaults` にまとめる。部分的に繰り返される長い共通本文は既存の `passages` / `passageId` を使う。ブラウザは展開後に従来と同じ検査を行い、生成側も全問の展開結果が元の問題と一致することを確認する。旧配列形式と旧索引も読み込める。原本ビルドの本文パックは変更しない。

文字化した問題の旧PNG URLも可逆圧縮の対象に含め、互換URLとして同じ画素を提供する。保存済みの編集・バックアップを維持するため、この互換画像は配信パッケージに残る。文字化による演習時の画像取得削減と、パッケージの保管容量削減を区別する。

`checks/native-evidence-check.py` は完成派生ビルドの全文字化問題を原本PDF・切り出し画素・最新の文字化条件と再照合する。本文・索引・旧画像URL・同期の検査は、JSONを圧縮した完成パッケージに対して行う。全スキャンの新規OCR、非可逆画像圧縮、原本の削除、本番配備はこの追加処理に含めない。
